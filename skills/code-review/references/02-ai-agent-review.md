# AI, LLM, RAG, and Multi-Agent Review

Use this pass only when the change touches prompts, model calls, tools, retrieval, agent routing,
memory, or agent state. The governing rule is the same as everywhere else: **flag what this
implementation actually does**, not what LLM systems in general might do. "The model could
hallucinate" is not a finding. "The answer is returned to the user with citations that are never
checked against the retrieved chunks (`rag.py:88`)" is.

---

## 1. Trust boundaries and prompt injection

**Senior question:** *Which text in this prompt came from someone other than us?*

- Retrieved documents, tool outputs, web pages, emails, file contents, and other agents' messages
  are **untrusted data**. Look for them being placed where they carry instruction authority — the
  system prompt, or wrapped in wording like "follow the instructions below".
- Injection matters in proportion to what the model can **do**. A summariser with no tools is a low
  risk; an agent that can send email, run SQL, or call payment APIs after reading a web page is high.
  Severity follows the most dangerous reachable tool.
- Untrusted content should be delimited and labelled as data, and high-impact actions should need
  a confirmation or a deterministic check outside the model.

## 2. Tools and permissions

**Senior question:** *If the model calls this tool with the worst arguments it could produce, what
happens?*

- Tool name looked up without handling unknown names (a hallucinated tool → `KeyError` → 500).
- Arguments passed straight from model output into the tool without schema validation (Pydantic,
  Zod, JSON Schema).
- Tools running with the service's credentials instead of the end user's permissions — the model
  becomes a confused deputy that can read any tenant's data.
- No allowlist per user, role, or agent; every agent can call every tool.
- Side-effecting tools (send, pay, delete, write) without idempotency keys — a retried step
  executes twice.

## 3. Agent loops, routing, and state

**Senior question:** *How does this loop end, and what happens when it doesn't?*

- `while True` or recursion with no max-iteration count, token budget, or wall-clock deadline.
  LangGraph: check `recursion_limit` and that the graph has a reachable `END` on every branch.
- Router or supervisor returning a label that maps to no node; no default route.
- Handoffs that drop context the next agent needs, or pass everything (context explosion).
- **State shape contracts:** a node writes a key another node reads with a different type or name.
  LangGraph: list fields without an `add` reducer overwrite instead of append; parallel branches
  writing the same key without a reducer raise or silently lose updates.
- **Session isolation:** checkpointer or memory keyed by something other than a per-user,
  per-conversation ID (`thread_id`); module-level dicts holding conversation state shared across
  requests; caches keyed without the user.
- Interrupts and human-in-the-loop: resuming with unvalidated input; side effects executed
  *before* the interrupt and repeated on resume.

## 4. Output handling

**Senior question:** *What does the code do when the model returns something unexpected?*

- `json.loads(raw)` or `JSON.parse` with no handling of malformed output; indexing `["key"]` on
  model output without checking it exists.
- No structured-output mode or schema validation where the code depends on structure.
- No fallback when output fails validation — retry once with the error, then degrade gracefully.
- Model output rendered as HTML or Markdown without sanitising (XSS through the model), or executed
  as code or SQL.

## 5. Grounding and RAG

**Senior question:** *Can the answer be traced back to the source it claims?*

- Citations generated by the model but never checked against the retrieved chunk IDs.
- Retrieval with no metadata filter for tenant, user, or permission — users retrieve each other's
  documents. This is a security finding, not a quality one.
- Chunking assumptions: chunk size versus the embedding model's limit; tables and code split
  mid-structure; no overlap where answers span boundaries.
- Embedding model changed without re-indexing (query and corpus vectors from different models).
- Empty retrieval handled as "answer anyway" instead of "say you don't know".
- `top_k` and score thresholds hard-coded with no evaluation behind them — usually Info, not a bug.

## 6. Cost, latency, and context

**Senior question:** *What does one request cost at the 99th percentile, and what bounds it?*

- Unbounded conversation history or tool output appended to the prompt — cost and latency grow
  per turn until the context limit throws.
- Independent model or tool calls made sequentially when they could run concurrently
  (only flag when latency matters on this path).
- The same LLM call repeated for identical input with no cache, or an expensive model used for a
  trivial classification step.
- Missing timeouts on model calls; retries without backoff on rate-limit (429) errors; no
  cancellation when the client disconnects.
- Streaming responses that hold resources after the client has gone.

## 7. Data protection and observability

- Full prompts, completions, or tool results logged at INFO with user PII, documents, or secrets.
- Traces (LangSmith, Langfuse, OpenTelemetry) shipping user data to third parties without the
  project's agreement to do so.
- No trace or run ID linking a user request to its model calls, tool calls, and agent hops —
  multi-agent failures become undebuggable.
- API keys passed into prompts, tool arguments, or state that gets checkpointed.

## 8. Evaluation and regression

- A prompt changed with no eval, golden set, or snapshot test showing behaviour did not regress.
- Output parsers changed without updating the prompt (or the reverse) — the pair must move together.
- Model version changed (`gpt-x` → `gpt-y`, `claude-…` → `claude-…`) without re-running evals.

---

## What not to flag

- Generic "LLMs can hallucinate" or "prompt injection is possible" with no reachable path to harm.
- Prompt wording preferences, unless the wording causes a concrete failure.
- Choice of framework (LangGraph vs plain code) unless the change shows a concrete cost.
- Missing "AI safety" layers on an internal L1 prototype with no tools and no user data.
